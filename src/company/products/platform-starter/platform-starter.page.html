What's a platform starter?

In a nutshell, it's the backbone of your new application's business logic until you need to scale. It's a Web API that handles the core necessities of your app, like authentication, data management, authorization, and encryption. You can extend it with your domain logic while it provides a stable and efficient core. This one is written in C#, built on top of ASP.NET; therefore, it is fast, efficient, and easy to maintain. It uses a modular monolith architecture, which makes it easy to navigate, extend, and scale when the time is right.

The problem it solves

Before AI, the IT sector's previous favorite buzzword was microservices. It was framed as the skeleton key of SaaS platforms, solving all your hardships in an instant. Truth is, opting into a microservice architecture is a maintenance burden a small company can easily choke on, and before a certain size it causes more problems than it solves. Consequently, as a conscious decision maker, you start your new application with a monolith until the architecture becomes a bottleneck. You need not worry about that, as when you get there, you will have more than enough revenue to decompose the whole thing into microservices.

So why a platform? Most new applications are started as small proof of concepts or prototypes, and never refactored thoroughly as developers are constantly racing against the clock. That is an anti-pattern, resulting in a weird mess of intertwined spaghetti code that is hard to maintain or develop further at a point. Platforms, on the other hand, are carefully engineered software products with extensibility, maintainability, scalability, and testability in mind. Every component works in a modular fashion, nicely and cleanly integrating into its surroundings. The downside is that designing a platform requires serious software engineering competence not available in every company.

So far so good, but there is a last question of utter importance. Why on Earth would you invest in a platform starter when writing code became almost free with AI? Quite counterintuitive, but that point makes the platform starter more relevant and valuable than ever. Can you make sure your AI-generated code will suite your business needs until it's time for decomposition? If so, you are a competent software engineer, or you have one in your team. Problem solved. Otherwise, you need a quality baseline crafted by a professional to compare all your future developments against.

Specification

  • Technology: C#, .NET 10
  • Architecture: modular monolith
  • Areas: public, admin
  • Tenancy: single-tenant
  • ORM: Linq2DB ORM with repository pattern, cross-table joins allowed, Fluent migrations for optional code-first DB management
  • Containerization: Docker, Docker Compose
  • Security: Argon2ID hashing, AES-256-GCM encryption, JWT, refresh tokens
  • Development: dynamic & interactive API documentation with Scalar, development profile container
  • Deployment: production profile HTTP container (reverse proxy with TLS required)
  • Code partitioning: Domain-Driven Design with technical partitions where sensible
  • Documentation: Draw.io editable SVG for C4, Markdown with MermaidJS for everything else
